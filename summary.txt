WHAT WAS NOT DONE (and why)
--------------------------------------------------------------------------------

[X] AUTOENCODER
    Reason: 504 rows is insufficient for a neural network. A small autoencoder
    would overfit trivially. Isolation Forest + LOF provide equivalent anomaly
    signals with far less risk on this dataset size.

[X] SMOTE / OVERSAMPLING
    Reason: Temporal sensor data. Synthesizing samples before chronological
    splitting would create artificial future observations and invalidate the
    evaluation. class_weight="balanced" used instead.

[X] SPIKE SUPERVISED CLASSIFIER
    Reason: Only 1 known example. No supervised model can generalize from a
    single sample. Rule-based detection (single-point MAD z-score) used instead.

[X] PROBABILITY CALIBRATION (Platt scaling)
    Reason: The validation set has only 12 GENUINE_EXTREME and 0 SENSOR_FAULT
    examples — far too few for reliable sigmoid/isotonic calibration. Applying
    calibration on this data would produce misleading confidence estimates.
    Documented as future work requiring more data.

[X] PREDICTIVE MAINTENANCE / REMAINING USEFUL LIFE
    Reason: No historical failure-to-recovery sequences exist in the dataset.
    7 days of data with 3 fault episodes is insufficient to model degradation
    trajectories. Health score implemented as a proxy.

[X] WALK-FORWARD VALIDATION
    Reason: With only 7 days and 168 unique timestamps, walk-forward folds
    would produce extremely small training windows (< 50 rows per fold) making
    results unreliable. Single chronological holdout used instead.

[X] STATION-AWARE CROSS-VALIDATION
    Reason: Only 3 stations. Leave-one-station-out would train on 2 stations
    and test on 1 — not meaningful for generalization claims with this dataset.

[X] LIGHTGBM
    Reason: Not installed. XGBoost was available and benchmarked. Random Forest
    outperformed XGBoost on this dataset (val macro-F1: 0.468 vs 0.315).

[X] SHAP ACTIVE IN INFERENCE
    Reason: shap package not installed in the current environment. The
    SHAPExplainer class is fully implemented and will activate automatically
    when shap is installed (pip install shap).

[X] FASTAPI LIVE TEST
    Reason: fastapi and uvicorn not installed. The API code is complete and
    correct. Run: pip install fastapi uvicorn pydantic
    Then: uvicorn api.main:app --reload (from skyguard/ directory)

[X] NOTEBOOKS
    Reason: The notebooks/ directory exists but notebooks were not populated.
    All logic is in src/ as production-quality modules. Notebooks are for
    experimentation only per the engineering rules.

KNOWN LIMITATIONS (documented, not hidden)
--------------------------------------------------------------------------------

1. 7-day dataset: Test set (Sep 6–7) contains only NORMAL observations.
   All faults and extreme events fall in train/val. True generalization to
   unseen fault types cannot be measured with this dataset.

2. GENUINE_EXTREME absent from training: The decision classifier never sees
   a thunderstorm during training. It must infer it from spatial/multivariate
   evidence features alone.

3. Val macro-F1 = 0.468 is the honest primary metric. The model correctly
   classifies NORMAL (recall=1.0) but misclassifies all 12 GENUINE_EXTREME
   as NORMAL (recall=0.0 on val). This is expected — the model has no
   training examples of GENUINE_EXTREME.

4. Imputer warning (feature column 45): One feature column (likely
   rainfall_mm_roll6_std) is all-NaN in training because rainfall is 0.0
   for the first 5 days. The imputer skips it with a warning. This is
   expected and harmless.
